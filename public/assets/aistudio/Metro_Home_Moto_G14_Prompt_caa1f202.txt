METRO HOME FOR MOTO G14
Implementation brief for Google AI Studio

Build a complete native Android launcher in Kotlin.
Use the attached screenshot as the art direction for the Start screen.
Deliver an installable debug APK when an Android build environment is available.
Always deliver the Android Studio project and reproducible build instructions.
Use English for code identifiers and Brazilian Portuguese for the interface.
The product is a Home app that runs on the stock Motorola Moto G14.
The phone must remain usable offline from its first launch.
Build the smallest working vertical slice first: Home role, Start grid, app launch, system Home return.
Next implement the lower command bar, app catalog, editing, persistence and live tiles.
Use the acceptance examples at the end to check the implementation.
Treat the example layouts and coordinates as test fixtures, never as content visible to users.

01 / ART DIRECTION
Match the arrangement on the phone screen in the supplied reference.
Use only the pixels inside the reference display as design guidance.
Fill the actual device screen with the launcher.
Begin below the real Android status bar.
Use black for the Start background and the spaces between tiles.
Start with a muted blue near #256D94.
Use white glyphs with strong silhouettes and restrained typography.
Use the device sans-serif family and a light weight for large numerals.
Choose a normal weight for app labels that must survive small sizes.
Use square corners and flat fills.
Place medium tile labels near their lower left corner.
Keep small tiles icon-only and expose the app name to assistive technology.
Fill the photo tile edge to edge using a center crop.
Make the day number the strongest element on the calendar tile.
Use vertical scrolling to reveal the next row of tiles.
Keep the Start screen free of marketing copy, decorative numbering and permanent titles.
Give the alphabetical list a large “Aplicativos” title in the Windows Phone tradition.
Use a compact pressed state on tap and honor the system motion setting.
Use original assets and locally available fonts.

02 / LOWER COMMAND BAR
Make the lower edge useful for one-handed operation.
Draw a black Metro command bar directly above the system navigation inset.
Match the neighboring system surface visually where Android permits.
Give the app-owned region a unique set of icons and accessible action names.
The Android gesture handle and three-button navigation area belong to System UI.
Let Android handle Home, Back, Overview and app switching in their reserved regions.
Keep every launcher touch target entirely inside app-owned space.
Do not use accessibility services, overlays, root or gesture exclusion to remap the system bar.
On Start, place Search on the left, Applications in the center and Edit on the right.
Use a magnifier, a four-square glyph and a pencil.
Place the three targets within reach of either thumb.
Use evenly sized action cells with a minimum touch height of 48 dp.
Tapping Search opens the app list with the search field focused.
Tapping Applications opens the complete list with the keyboard hidden.
Tapping Edit enters tile-editing mode at the current scroll position.
In edit mode, switch the bar to contextual commands for the selected tile.
Provide Resize, Unpin and Done; expose Move through the tile context menu as well as dragging.
Show the size choices in a sheet anchored above the bar.
Selecting Done commits the staged arrangement atomically.
Pressing Back with pending edits offers Save, Discard and Continue editing.
In search mode, yield space to the keyboard and keep focused results visible.
In settings, use the Android Back action to return to the previous launcher surface.
Expose settings through an overflow action in the app list.
Anchor sheets to the current usable bounds after the keyboard opens or closes.
Apply navigation insets once at the container that owns the bottom edge.
Set bottom content padding so the last tile clears the full command bar.
Handle navigation changes while the launcher is running.
Read current insets instead of guessing the active navigation mode from the device model.

03 / NATIVE IMPLEMENTATION
Use one application module and a small, understandable state model.
Choose a native view toolkit appropriate for a recycled scrolling tile surface.
Include compatible Gradle, Android Gradle Plugin, Kotlin and SDK versions.
Declare a properly exported Home activity for MAIN, HOME and DEFAULT.
Provide an ordinary entry point for first-run setup before Home selection.
Handle repeated Home intents in the existing launcher task.
Use the system Home role request when available.
Provide the system Home settings fallback when appropriate.
Query launchable activities through Android's launcher facilities.
Scope discovery to supported profiles and accessible activities.
Identify each target by component and profile, never by display label alone.
Observe app availability changes while the launcher is active.
Refresh after foreground return to cover changes made while it was stopped.
Resolve a live target at launch time and recover from missing activities.
Persist the layout locally with a versioned schema.
Keep a stable tile ID separate from the app identity.
Store grid coordinates and spans in units; derive pixel bounds at layout time.
Make every layout save an atomic operation.
Keep a staged working copy during editing.
Preserve an intentional empty screen across restarts.
Treat first launch and an intentionally empty layout as different states.
Use local resources for all interface copy and plurals.
Support physical keyboard focus, TalkBack, font scaling and reduced motion.
Request photo access through a user-initiated system picker.
Retain access to the selected image through a supported grant or a bounded local copy.
Use lifecycle-aware updates for the clock, calendar and battery.
Load installed icons asynchronously and bound decoded bitmap memory.
Refresh visible tiles only when their underlying values change.
Keep search on the device and avoid analytics, accounts and advertisements.
Make the release experience usable without network permissions.
Profile a release-like build where measurements are supported.
Separate physical Moto G14 measurements from emulator observations.
Never claim a frame rate, battery saving or tested build without evidence.

04 / INTERACTION CONTRACTS
Each record below describes a user action and its observable result.
First run
  Given: Fresh install.
  Action: Open the launcher from the app list.
  Expected: Seed the reference layout using available local targets.
  Continuity: Offer “Definir como início” in settings.
Home selection
  Given: Launcher is open in preview.
  Action: Request the Home role.
  Expected: Android presents its own selection screen.
  Continuity: Return to Start if the user dismisses the chooser.
Return home
  Given: Another app is in front.
  Action: Use the system Home action.
  Expected: Show Start in the existing task.
  Continuity: Retain the saved grid and scroll predictably.
App launch
  Given: A valid app tile is visible.
  Action: Tap once.
  Expected: Start the component associated with that tile.
  Continuity: Ignore an accidental second tap during handoff.
Missing app
  Given: A component disappeared after binding.
  Action: Tap its tile.
  Expected: Refresh its availability and explain the change.
  Continuity: Offer removal of the stale shortcut.
Open list
  Given: Start is visible.
  Action: Tap Aplicativos in the lower bar.
  Expected: Show locally installed, launchable apps.
  Continuity: Keep the keyboard closed.
Open search
  Given: Start is visible.
  Action: Tap Buscar in the lower bar.
  Expected: Focus the search field and show the keyboard.
  Continuity: Keep at least one result row reachable.
Filter
  Given: Search contains text.
  Action: Type part of an app name.
  Expected: Update the results from the local catalog.
  Continuity: Match accented labels with an unaccented query.
Clear query
  Given: Search contains text.
  Action: Activate Limpar busca.
  Expected: Restore all visible catalog entries.
  Continuity: Keep focus in the input field.
No matches
  Given: The query matches no installed app.
  Action: Inspect the results.
  Expected: Show Nenhum aplicativo encontrado.
  Continuity: Offer a single action to clear the query.
Pin
  Given: An app is visible in the list.
  Action: Long-press and choose Fixar no início.
  Expected: Add it to a fitting open position.
  Continuity: Persist the pin independently of future catalog refreshes.
Duplicate pin
  Given: A matching app already has a tile.
  Action: Open the pin action again.
  Expected: Identify the existing pin.
  Continuity: Offer to locate its tile.
Open editing
  Given: A long grid has been scrolled.
  Action: Tap Editar.
  Expected: Enter edit mode at the same viewport.
  Continuity: Select a tile by tapping it.
Choose size
  Given: One tile is selected.
  Action: Tap Tamanho.
  Expected: Present the supported sizes for that tile.
  Continuity: Indicate the current size.
Grow a tile
  Given: A larger size would collide.
  Action: Choose the larger span.
  Expected: Preview a deterministic reflow or offer a fitting position.
  Continuity: Keep every displaced tile reachable.
Move by touch
  Given: Edit mode has a selected tile.
  Action: Drag to a valid cell and release.
  Expected: Show the staged position.
  Continuity: Finish to commit the change.
Move accessibly
  Given: TalkBack is enabled.
  Action: Choose Mover from the tile actions.
  Expected: Offer directional steps with spoken positions.
  Continuity: Allow confirmation without dragging.
Unpin
  Given: A pinned app is selected.
  Action: Tap Desafixar.
  Expected: Remove its tile from the staged grid.
  Continuity: Keep the installed app in the catalog.
Discard edit
  Given: A staged move is pending.
  Action: Press Back and choose Descartar.
  Expected: Restore the previously saved grid.
  Continuity: Return focus to the original tile when present.
Commit edit
  Given: Several edits are pending.
  Action: Tap Concluir.
  Expected: Save one complete layout revision.
  Continuity: Exit edit mode only when the save succeeds.
Save failure
  Given: Storage cannot accept the edit.
  Action: Tap Concluir.
  Expected: Show a readable error and retain the draft.
  Continuity: Offer another save attempt.
Use clock
  Given: A clock app is available.
  Action: Tap the time tile.
  Expected: Open a supported clock or alarms destination.
  Continuity: Display the device time format on the tile.
Pick photo
  Given: The photo tile has no image.
  Action: Tap Escolher foto.
  Expected: Launch the system picker.
  Continuity: Retain the previous state if canceled.
Replace photo
  Given: A photo is already configured.
  Action: Choose Trocar foto.
  Expected: Replace the image after successful decoding.
  Continuity: Release unused access to the previous image.
Lost photo
  Given: The stored image is unavailable.
  Action: Return to Start.
  Expected: Show a lightweight photo placeholder.
  Continuity: Offer Escolher foto on the tile.
Calendar
  Given: A month boundary passes.
  Action: Resume the launcher.
  Expected: Show the current local date.
  Continuity: Use the device time zone for the transition.
Battery
  Given: The battery level changes.
  Action: Return to Start.
  Expected: Show the reported percentage when available.
  Continuity: Provide a neutral label for an unknown level.
Accent
  Given: Personalization is open.
  Action: Choose a supported accent.
  Expected: Preview the color on representative tiles.
  Continuity: Preserve accessible text contrast.
Reduced motion
  Given: System animations are disabled.
  Action: Open the app list.
  Expected: Present the destination immediately.
  Continuity: Preserve the same focus destination.
Empty grid
  Given: The final tile was removed and saved.
  Action: Restart the launcher.
  Expected: Show a simple path to Aplicativos.
  Continuity: Do not repeat the first-run seed.
Offline
  Given: Airplane mode is enabled.
  Action: Open Start and search.
  Expected: Return results from the installed catalog.
  Continuity: Keep the clock and local photo operational.
Keyboard return
  Given: A search result has focus.
  Action: Press Enter.
  Expected: Open the selected app.
  Continuity: Home remains available through the operating system.
Screen reader
  Given: An icon-only tile has focus.
  Action: Ask TalkBack to read it.
  Expected: Announce the actual app or action name.
  Continuity: Expose pin and move operations through named actions.
Navigation mode change
  Given: The device switches system navigation modes.
  Action: Return to the launcher.
  Expected: Lay out the bottom bar against the new inset.
  Continuity: Keep the last row and menu reachable.
Process recreation
  Given: Android reclaims the launcher process.
  Action: Press Home.
  Expected: Load the last committed layout.
  Continuity: Discard any partial disk write.
Catalog update
  Given: An app changes label or icon.
  Action: Resume the app list.
  Expected: Refresh its presentation.
  Continuity: Keep its pinned position when the component is stable.
Font scaling
  Given: The user enlarges device text.
  Action: Open a long app label.
  Expected: Preserve reading order and access to its full name.
  Continuity: Allow supporting text to wrap where appropriate.
Rotation
  Given: The window width changes.
  Action: Recompute tile bounds.
  Expected: Keep logical order and saved unit positions.
  Continuity: Restore focus by stable tile ID.
System Back
  Given: A chooser is above an edit screen.
  Action: Invoke Back.
  Expected: Dismiss the chooser first.
  Continuity: Keep the underlying edit session active.
Search dismissal
  Given: The keyboard covers the search screen.
  Action: Use system Back.
  Expected: Allow the IME to close first.
  Continuity: A subsequent Back returns to the previous surface.
